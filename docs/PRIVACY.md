# Privacy

[Deutsch](#datenschutz)

Tunero has no telemetry, no accounts, no ads and no analytics. Scan results, backups, settings and logs stay on your PC in `%ProgramData%\Tunero`. A Markdown report (`--report`) is written only to the file you name.

The app contacts the internet only for the features below, and only when you start them or turn them on.

| Feature | When | What is sent, and to whom |
|---|---|---|
| Update check (Settings > Updates) | Off by default. At start when you turn it on, or when you click "Check now" | One HTTPS request to `api.github.com` for the latest release. GitHub sees your IP address and the app version (for example `Tunero/0.4.7`). When you click "Update now" and confirm, the exe, its SHA-256 file and its signature file (`.sig`) are downloaded from this repository's GitHub release (`github.com`, which hands the files out from `githubusercontent.com`; user agent `Tunero/update`), checked, and swapped for the running exe. A copy installed with winget, Chocolatey or Scoop hands the update to that package manager instead: it downloads the new version from the same GitHub release, using the address and checksum from its own repository (the winget repository, the Chocolatey community repository, or the Tunero bucket for Scoop on GitHub), and contacts that repository as it always does. |
| VirusTotal lookup (Startup page) | Only with your own API key, when you start a lookup | The SHA-256 hash of each checked file and your API key go to `virustotal.com`. Files are never uploaded. The key is stored DPAPI-encrypted for your Windows account. |
| DNS benchmark (Graphics & DNS) | When you start it | DNS queries for ten popular domains (Google, YouTube, Steam, Twitch, Discord, Microsoft, Reddit, Amazon, Wikipedia, Epic Games) to your current DNS servers and to Cloudflare, Google, Quad9, OpenDNS and AdGuard DNS. |
| DNS presets (Graphics & DNS) | When you apply one | Nothing is sent by the app. Your PC then uses that provider for DNS, so the provider sees the names your PC looks up. |
| App installs and updates, the PawnIO sensor driver | When you install something or select "Update all apps" | winget downloads the package from its source (Microsoft's winget repository and the vendor's servers). If Chocolatey or Scoop is installed, "Update all apps" also runs it: each contacts its own sources (the Chocolatey community repository or the sources you set up, Scoop's buckets on GitHub) and the vendors' servers. The Microsoft Store only opens its updates page; it contacts Microsoft when you select Get updates there. |
| Chocolatey updates (Install & update) | When you select "Check Chocolatey updates" or Update on one of its packages | Chocolatey asks its sources for newer versions (`choco outdated`) and downloads the update you start. |
| Adding a Windows capability or turning on a Windows feature (Tools) | When you add one | DISM downloads the capability, or the files of a feature such as .NET Framework 3.5, from Windows Update. |
| Sync the clock (Tools > Fixes and repair) | When you run it | The Windows Time service asks its configured time server (`time.windows.com` unless you changed it) for the time. |
| Repair with DISM (Tools > Fixes and repair) | When you start it | Windows downloads repair files from Windows Update. |
| Update Microsoft Defender (Tools > Fixes and repair) | When you run it | Microsoft Defender downloads its latest definitions from its configured update source (Microsoft Update unless your company set another). |
| Search winget (Install & update) | When you search | winget reads its package catalog from Microsoft (`cdn.winget.microsoft.com`); the search itself runs on your PC. |
| Check for updates (Install & update) | When you click it | winget reads its package catalog from Microsoft (`cdn.winget.microsoft.com`) and compares it on your PC with what is installed. Nothing is installed or sent about your apps. |
| Reset winget sources (Tools > Fixes and repair) | When you run it | winget sets up its default sources again and downloads their catalog from Microsoft. |
| Windows install media (Windows install media page) | When you click "Check for the newest version", and when you build from the download | One request to `fe3.delivery.mp.microsoft.com`, Microsoft's media catalog search (the one the Media Creation Tool uses; Microsoft does not document it), with exactly this body: `{"Products":"PN=Windows.Products.Cab.amd64&V=0.0.0.0","DeviceAttributes":"DUScan=1;OSVersion=10.0.26100.1"}`. Then the catalog (`products.cab`) and, when you build, the Windows image you chose are downloaded from `dl.delivery.mp.microsoft.com` and other `delivery.mp.microsoft.com` hosts, over HTTP; every file is checked by the SHA-256 from Microsoft's signed catalog. Microsoft sees your IP address; nothing about your PC is sent beyond the body above. Building from your own ISO uses no network. |
| Apps installed at the first sign-in (Windows install media page, Install apps) | Only on a PC installed from an ISO where you ticked apps under Install apps, once, at its first sign-in | The copied Tunero runs winget for each ticked app: winget reads its catalog from Microsoft (`cdn.winget.microsoft.com`) and downloads the package from its source (Microsoft's winget repository and the vendor's servers), as when you install an app on Install & update. Without internet nothing is downloaded and the result names the apps that were not installed. |
| Links (Store pages, driver pages, sources, GitHub, Ko-fi under Settings > About) | When you click one | Opens in your browser. "Report a problem" opens GitHub's bug form with the app version and the Windows build in the link, so GitHub receives both when the page opens; the report itself is sent only when you submit it there. |
| Error report (after an unexpected error) | Only when you click "Open report" in the question the app shows after the error, or on the next start | Opens GitHub's bug form in your browser, filled in with the app version, the Windows build and the error details (error type, message and the program lines where it happened). Profile paths, your Windows user name and the computer name are removed first. The text is in the link, so GitHub receives it when the page opens; the report is only sent when you submit it there. Until then the error is kept in the data folder only. |

The frame time benchmark uses PresentMon, which is built into the exe and runs locally. Sensor readings stay local.

The storage analysis (Storage page) runs on your PC and sends nothing. Analyze reads the names, sizes and dates of the files on the drive or folder you chose; Find duplicates reads the content of files of the same size to compare them (files that are only in OneDrive's cloud are left out, because reading them would download them). The result stays in memory until you close it or the app. The log records counts and times, not file names; only what you move to the Recycle Bin is logged with its path. Open in Explorer starts File Explorer on your PC, and Copy path puts the paths on your clipboard.

The Wi-Fi check reads the band of the connected Wi-Fi network through the Windows Wi-Fi API. Windows gives desktop apps this information only when location access is allowed for them, and may ask you the first time ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes)). Without that permission the check shows "unknown". The information stays on your PC.

# Datenschutz

Tunero hat keine Telemetrie, keine Konten, keine Werbung und keine Analyse. Scan-Ergebnisse, Sicherungen, Einstellungen und Protokolle bleiben auf deinem PC in `%ProgramData%\Tunero`. Ein Markdown-Bericht (`--report`) wird nur in die Datei geschrieben, die du angibst.

Die App geht nur für die folgenden Funktionen ins Internet, und nur wenn du sie startest oder einschaltest.

| Funktion | Wann | Was gesendet wird, und an wen |
|---|---|---|
| Update-Prüfung (Einstellungen > Updates) | Standardmäßig aus. Beim Start, wenn du sie einschaltest, oder bei "Jetzt prüfen" | Eine HTTPS-Anfrage an `api.github.com` nach der neuesten Version. GitHub sieht deine IP-Adresse und die App-Version (zum Beispiel `Tunero/0.4.7`). Erst wenn du auf "Jetzt aktualisieren" klickst und bestätigst, werden die exe, ihre SHA-256-Datei und ihre Signaturdatei (`.sig`) aus dem GitHub-Release dieses Repositorys geladen (`github.com`, das die Dateien über `githubusercontent.com` ausliefert; User-Agent `Tunero/update`), geprüft und gegen die laufende exe getauscht. Eine mit winget, Chocolatey oder Scoop installierte Kopie übergibt das Update stattdessen an diesen Paketmanager: Er lädt die neue Version aus demselben GitHub-Release, mit Adresse und Prüfsumme aus seinem eigenen Verzeichnis (dem winget-Verzeichnis, dem Chocolatey Community Repository oder dem Tunero-Bucket für Scoop auf GitHub), und fragt dieses Verzeichnis wie sonst auch ab. |
| VirusTotal-Abfrage (Autostart) | Nur mit deinem eigenen API-Schlüssel, wenn du eine Abfrage startest | Der SHA-256-Hash jeder geprüften Datei und dein API-Schlüssel gehen an `virustotal.com`. Dateien werden nie hochgeladen. Der Schlüssel wird mit DPAPI für dein Windows-Konto verschlüsselt gespeichert. |
| DNS-Benchmark (Grafik & DNS) | Wenn du ihn startest | DNS-Anfragen nach zehn bekannten Domains (Google, YouTube, Steam, Twitch, Discord, Microsoft, Reddit, Amazon, Wikipedia, Epic Games) an deine aktuellen DNS-Server und an Cloudflare, Google, Quad9, OpenDNS und AdGuard DNS. |
| DNS-Vorgaben (Grafik & DNS) | Wenn du eine anwendest | Die App sendet nichts. Dein PC nutzt danach diesen Anbieter für DNS, der Anbieter sieht also die Namen, die dein PC nachschlägt. |
| App-Installationen und -Updates, der PawnIO-Sensortreiber | Wenn du etwas installierst oder "Alle Apps aktualisieren" wählst | winget lädt das Paket aus seiner Quelle (Microsofts winget-Verzeichnis und die Server des Herstellers). Sind Chocolatey oder Scoop installiert, führt "Alle Apps aktualisieren" sie ebenfalls aus: Jeder fragt seine eigenen Quellen ab (das Chocolatey Community Repository oder die von dir eingerichteten Quellen, die Buckets von Scoop auf GitHub) und die Server der Hersteller. Der Microsoft Store öffnet nur seine Seite für Updates; er fragt Microsoft, wenn du dort "Updates abrufen" wählst. |
| Chocolatey-Updates (Installieren & aktualisieren) | Wenn du "Chocolatey-Updates suchen" oder bei einem seiner Pakete "Aktualisieren" wählst | Chocolatey fragt seine Quellen nach neueren Versionen (`choco outdated`) und lädt das Update, das du startest. |
| Hinzufügen einer optionalen Funktion oder Einschalten eines Windows-Features (Tools) | Wenn du eine hinzufügst | DISM lädt die Funktion, oder die Dateien eines Features wie .NET Framework 3.5, über Windows Update. |
| Uhr synchronisieren (Tools > Hilfen und Reparatur) | Wenn du es startest | Der Windows-Zeitdienst fragt seinen eingestellten Zeitserver (`time.windows.com`, wenn du nichts geändert hast) nach der Uhrzeit. |
| Reparatur mit DISM (Tools > Hilfen und Reparatur) | Wenn du sie startest | Windows lädt Reparaturdateien von Windows Update. |
| Microsoft Defender aktualisieren (Tools > Hilfen und Reparatur) | Wenn du es startest | Microsoft Defender lädt seine neuesten Definitionen von seiner eingestellten Updatequelle (Microsoft Update, wenn deine Firma keine andere eingestellt hat). |
| winget durchsuchen (Installieren & aktualisieren) | Wenn du suchst | winget liest seinen Paketkatalog von Microsoft (`cdn.winget.microsoft.com`); die Suche selbst läuft auf deinem PC. |
| Nach Updates suchen (Installieren & aktualisieren) | Wenn du darauf klickst | winget liest seinen Paketkatalog von Microsoft (`cdn.winget.microsoft.com`) und vergleicht ihn auf deinem PC mit dem, was installiert ist. Nichts wird installiert, nichts über deine Apps gesendet. |
| winget-Quellen zurücksetzen (Tools > Hilfen und Reparatur) | Wenn du es startest | winget richtet seine Standardquellen neu ein und lädt ihren Katalog von Microsoft. |
| Windows-Installationsmedium (Seite Windows-Installationsmedium) | Wenn du auf "Nach neuester Version suchen" klickst, und wenn du das Medium aus dem Download erstellst | Eine Anfrage an `fe3.delivery.mp.microsoft.com`, Microsofts Suche im Medienkatalog (dieselbe, die das Media Creation Tool nutzt; Microsoft dokumentiert sie nicht), mit genau diesem Inhalt: `{"Products":"PN=Windows.Products.Cab.amd64&V=0.0.0.0","DeviceAttributes":"DUScan=1;OSVersion=10.0.26100.1"}`. Danach werden der Katalog (`products.cab`) und beim Erstellen das gewählte Windows-Abbild von `dl.delivery.mp.microsoft.com` und anderen Hosts unter `delivery.mp.microsoft.com` über HTTP geladen; jede Datei wird mit der SHA-256-Prüfsumme aus Microsofts signiertem Katalog geprüft. Microsoft sieht deine IP-Adresse; über den Inhalt oben hinaus wird nichts über deinen PC gesendet. Das Erstellen aus deiner eigenen ISO nutzt kein Netzwerk. |
| Apps bei der ersten Anmeldung (Seite Windows-Installationsmedium, Apps installieren) | Nur auf einem PC, der von einer ISO installiert wurde, auf der du unter Apps installieren Apps angehakt hast, einmal bei seiner ersten Anmeldung | Das kopierte Tunero startet winget für jede angehakte App: winget liest seinen Katalog von Microsoft (`cdn.winget.microsoft.com`) und lädt das Paket aus seiner Quelle (Microsofts winget-Verzeichnis und die Server des Herstellers), wie beim Installieren einer App unter Installieren & aktualisieren. Ohne Internet wird nichts geladen, und das Ergebnis nennt die Apps, die nicht installiert wurden. |
| Links (Store-Seiten, Treiberseiten, Quellen, GitHub, Ko-fi unter Einstellungen > Über) | Wenn du einen anklickst | Öffnet sich in deinem Browser. „Problem melden“ öffnet das Fehlerformular auf GitHub mit App-Version und Windows-Build im Link, GitHub erhält beides also beim Öffnen der Seite; der Bericht selbst wird erst gesendet, wenn du ihn dort abschickst. |
| Fehlerbericht (nach einem unerwarteten Fehler) | Nur wenn du in der Frage, die die App nach dem Fehler oder beim nächsten Start zeigt, auf "Bericht öffnen" klickst | Öffnet das Fehlerformular auf GitHub in deinem Browser, ausgefüllt mit App-Version, Windows-Build und den Fehlerdetails (Fehlerart, Meldung und die Programmzeilen, in denen er auftrat). Profilpfade, dein Windows-Benutzername und der Computername werden vorher entfernt. Der Text steht im Link, GitHub erhält ihn also beim Öffnen der Seite; gesendet wird der Bericht erst, wenn du ihn dort abschickst. Bis dahin liegt der Fehler nur im Datenordner. |

Der Frametime-Benchmark nutzt PresentMon, das in der exe enthalten ist und lokal läuft. Sensorwerte bleiben lokal.

Die Speicheranalyse (Seite Speicher) läuft auf deinem PC und sendet nichts. Analysieren liest Namen, Größen und Datumsangaben der Dateien auf dem gewählten Laufwerk oder Ordner; Duplikate suchen liest den Inhalt gleich großer Dateien, um sie zu vergleichen (Dateien, die nur in der OneDrive-Cloud liegen, bleiben außen vor, weil das Lesen sie herunterladen würde). Das Ergebnis bleibt im Arbeitsspeicher, bis du es oder die App schließt. Das Protokoll hält Anzahlen und Zeiten fest, keine Dateinamen; nur was du in den Papierkorb verschiebst, wird mit seinem Pfad protokolliert. Im Explorer öffnen startet den Explorer auf deinem PC, und Pfad kopieren legt die Pfade in deine Zwischenablage.

Die WLAN-Prüfung liest das Frequenzband des verbundenen WLANs über die Windows-WLAN-Schnittstelle. Windows gibt Desktop-Apps diese Information nur, wenn der Standortzugriff für sie erlaubt ist, und fragt beim ersten Mal eventuell nach ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes)). Ohne diese Erlaubnis zeigt die Prüfung „unbekannt“. Die Information bleibt auf deinem PC.
