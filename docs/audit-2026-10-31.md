# Repository audit, 2026-10-31

Main at `b2d710a` (1.5.31), clean tree. Scope: every file of the app (Core and WPF), the tests, CI and scripts, the catalog and all 614 explanation pages, the repo docs and the website, plus a UI review from 190 screenshots.

**Method.**
- **Code:** 25 reviewers each read one area line by line: Core in ten areas, the app in eight (including both resx files), catalog data, English pages, German pages, tests, build and CI, repo docs, website. A further reviewer covered cross-cutting concerns (architecture, duplication, layering, dependencies, and the open TODO items A to C).
- **UI:** every page was rendered in Light and Dark, English and German, plus scrolled, 1040 px wide and 760 px high variants, page tabs, dialogs, demo states and a theme switch while open: 190 PNGs. Seven reviewers looked at them, six by page group and one across pages.
- **Verification:** every finding went to a skeptic agent that re-read the code or the screenshot and tried to refute it. 40 findings were dropped there (7 code, 33 UI). I re-checked the four that stayed high myself, against the code and the screenshots.

**Baseline.** `dotnet build -c Release`: 0 errors, 0 warnings. `dotnet test -c Release --no-build --filter "Category!=Hardware"`: all 2454 tests pass (2122 Core, 332 App). `dotnet list package --vulnerable --include-transitive`: nothing. `npm audit` in `website/`: 3 low (deepmerge prototype poisoning, a dev dependency of the build).

## Summary

**No critical finding, and no high code finding.** The engine, undo and backups, the media build, the native layouts, SafeDelete and the elevation boundary held up again. The four high findings are all UI:

1. **Raw INF names on Startup > Services and Drivers** (U1, U4). `StartupScanner.ResolveIndirect` hands `@oem19.inf,%Name%;Fallback` to `SHLoadIndirectString`, which cannot resolve the INF form, so rows read `@oem19.inf,%ServiceDisplayName%;Intel(R) ...`. Confirmed in `startup-tab2-*.png` and at `src/Optimizer.Core/Startup/StartupScanner.cs:441`. Fix: fall back to the text after the last `;`, as services.msc does.
2. **Graphics & DNS without graphics** (U2, U10). On a PC without NVIDIA or AMD settings the page shows only DNS under a title and subtitle that promise driver settings and game profiles, and it does not say why. Confirmed in `network-*.png`.
3. **Clipped links at 1040 px** (U3, U11). The two link lines in the DNS card are cut mid-word ("in der Gru", "unter Toc"). Confirmed in `network-narrow-dark-de.png`.

The medium findings fall into four groups:
- **Pages that say something different from what they show.** The Overview verdict says nothing slows the PC (100 of 100) while it lists a security-lowering setting under "works against the profile". "Hide Windows entries" leaves Windows entries in the list. A service switch labeled Disabled sets Manual. A failed install media build is visible only at the bottom of the page.
- **Navigation that lands on nothing.** Details on a works-against line, or a search result for a filtered or Expert tweak, opens a Tweaks page that does not show the tweak.
- **Startup inspection details.** Startup folder files, shortcut targets and InprocServer32 DLL paths are parsed as command lines, so a planted `<prefix>.exe` is checked instead of the real file. The rundll32 entry point is missed when the DLL is quoted.
- **Content.** `privacy.inkingTypingOff` deletes the personal dictionary but is marked reversible and batch safe. The German VBS summary drops the anti-cheat warning. The `intelLocked` board pattern misses Z590. One recovery command repeats the tweak instead of undoing it.
